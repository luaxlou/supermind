# Supermind 定位与工程边界

## 当前定位

2026-09-09，用户明确将 Supermind 定位为 Codex 平台下的能力，并剥离需求分析和全部设计相关能力。Supermind 通过 Codex 插件提供工程执行实践、能力复用与持续记忆，承接已明确的上游成果，完成工程落地。

本决定替代此前“独立 Agent”“覆盖构想、需求与设计的完整软件生命周期”等定位。用户与 ChatGPT 的上游协作负责需求分析、产品构想、价值取舍、业务建模、架构和系统设计、接口契约以及 UI 与交互设计。Supermind 不再提供这些能力，也不通过其他插件间接执行。

## 工程职责

- 承接当前范围的有效需求、设计及验收依据，读取既有实现与工程约束。
- 拆解既定方案，编码、集成、调试、修复、重构，以及在现行契约和架构内优化。
- 按有效授权与必要证据处理测试、审查、版本、集成、交付、发布和运行维护。
- 按已确认的安排完成迁移与退出，记录真实结果及遗留问题。
- 检索、评估、接入工程能力，从真实实践中积累代码、工具与工程方法。

实施计划和常规代码细节属于工程执行，不要求上游给出每个函数或操作步骤。改变业务规则、系统边界、接口契约和用户体验则需要上游决定。当前范围依据足够即可工作，不强制正式文档或全产品先行定稿。

## 上游交接与反馈

先读已有资料。遇到需求或设计缺口时，整理具体问题、已有事实、冲突与工程影响，交回用户或 ChatGPT；不自行生成替代方案或将代码现状改写为新需求。只暂停依赖缺口的部分，继续其他已授权工作。收到明确修订后更新受影响的实施与验证内容。

纯需求或设计请求说明边界并整理已有输入供上游承接，不自动启动实现。工程技术解释、调查和可行性反馈仍属于 Supermind。交接不绑定特定文档模板或 ChatGPT 接口；目前没有自动跨平台交接功能。

现行运行指引由[技能入口](../../plugins/supermind/skills/supermind/SKILL.md)、[工程决策](../../plugins/supermind/skills/supermind/references/core-decision.md)、[工程场景](../../plugins/supermind/skills/supermind/references/scenarios.md)及[上游成果承接](../../plugins/supermind/skills/supermind/references/implementation-input.md)维护。

## 复用与持续记忆

能力从真实使用、结果和反馈中生长，不以预设演练作为成立前提。用户明确无需验证时不追加检查；结果、推测与未知如实表达。重要工程认识更新原有材料，沿用已有 Git 和同步机制，不另建独立 Agent 状态系统。

工程能力需要真实载体、可获取来源、通用边界和收益依据。分类、抽象、验证与授权分别判断，沉淀与具体采用遵守有效确认规则。工程能力检索在场景规定时点执行，故障不能解释为空库；普通局部修改和技术解释不以库配置为前提。

需求分析、UI 线框、业务流程图设计及原有基线方法调用指引已移入[历史归档](../archive/requirements-and-design/README.md)。新的工程任务不调用或沉淀需求与设计方法，包含这些活动的通用方法也不能间接启动它们。

独立能力库的历史 `product`、`design` 分类与 `begin-design` 命令保留兼容性，不代表 Supermind 提供相应能力。后者仅用于既有工程检索协议。私有库中的历史记录不自动删除，明确的库管理请求按现有工具和授权处理。定位调整未改变运行时或存储协议；0.7.0 发布时将现有能力库源码重新打包为 0.3.17，修正此前分发包与源码不一致的问题。

## 工具与交付边界

Codex 是执行平台。Superpowers 和其他插件是可选的工程工具来源，按实际适用性和项目约束调用；需求分析、头脑风暴与设计流程不作为工程前置条件。

源码修改、发布与更新已安装插件是不同结果。0.7.0 的定位调整落在仓库文档、技能和插件元数据；发布与本机更新按用户明确授权执行。

### 0.4.0 的验证记录

2026-09-07，修改前的独立基线演练中，“先讨论功能价值”和“只解释退出服务事项”都选择先运行能力库初始化。前者原始回答包括：“若报告未配置，我需要先知道：你准备使用哪个 GitHub 私有仓库？”这与讨论不依赖库的范围不符。

修改后的独立演练覆盖上述情境，以及非软件文案、改向身份网关试用、仅评估工程经验、检索故障下赶发布、无仓库的新应用构想，共七例。讨论类情境未选择初始化，非软件任务未进入，试用保留具体复用确认，候选评估未写库，检索失败未以新建或手测成功绕过。演练没有真实执行命令或更改数据，不等于运行时端到端验证。

分发结构、技能与插件清单校验通过；插件启动器的 20 项测试通过。此次未修改 Python 运行时，继续锁定 0.3.7 工具包，未重跑整个能力库集成测试集。
