# PRD 业务流程图：Enterprise Process Map + BPMN semantics

> 历史归档（2026-09-09）：已退出 Supermind 当前能力范围，仅保留原有内容供追溯，不作为工程任务的调用指引。现行边界见 [Supermind 定位](../../product/supermind-decision-model.md)。

## 定位与触发

面向业务、管理层和产品读者，将需求材料转为适合嵌入 PRD 的核心业务流程图。用于新绘制或美化跨角色业务流程、审批、交接与异常回流，以及统一一组流程图的视觉母版。用 Enterprise Process Map 表达视觉层级，保留 BPMN 的关键逻辑；不宣称图形符合完整 BPMN 2.0 标准或可供流程引擎执行。

这是一份可独立采用的设计方法。采用者读取本文、提供业务输入，使用能精确控制文本、泳道和连线并导出矢量图的工具即可开始；不依赖特定插件、原文档或原作者。预期收益是减少重复选择风格和修复图面噪声，尚不代表已有量化收益或真实跨项目验证。

## 输入与输出

输入至少包含：流程目的和边界、开始与结束条件、参与角色及职责、动作顺序、判断条件及各分支去向、异常与重新进入位置。批量绘制还需流程清单；嵌入文档时提供页面方向、可用宽度和输出格式要求。

先从已有材料提取上述事实。缺少影响路径的规则时明确标为待确认，可继续设计已知部分，但不能自行发明审批角色、金额阈值或终止条件。待确认版本不作为最终业务流程交付。

输出包含可编辑的图形源文件或结构化源稿、用于阅读或嵌入文档的静态图，以及图外的未决事项（如有）。推荐 SVG 作为矢量输出；必要时另导出 PNG 或 PDF。图像生成可辅助风格探索，但业务文字、判断、箭头方向和回流路径必须能精确校验和修改。

## 先整理逻辑

1. 为动作与判断设稳定标识，列出每项所属角色、简短名称和必要业务信息，再列出起点、终点、连线条件与回流目标。角色决定泳道；阶段决定横向次序，两者不要混为同一维度。
2. 找出最常见的成功路径作为视觉主流程，以从左向右为默认方向。判断分支写明确条件，不能仅靠颜色说明通过或拒绝。互斥选择与并行处理必须区别；并行拆分和汇合要成对表达，不能用普通判断冒充。
3. 保留职责交接、开始/结束、必要判断与异常回流。返工需要连接到实际重新执行的动作；终止需要独立结束。分支先画对，再降低视觉权重，不能为了简洁删掉必要路径。
4. 同一参与方内部可使用任务间顺序箭头。不同独立组织间若存在消息交互，应明确消息与顺序关系；涉及复杂事件、事务或可执行模型时改用标准 BPMN 工具。

## 默认视觉母版

以下是这套 PRD 风格的默认值；用户明确给定的品牌、版式或可读性要求优先。

- 画布：1920×1200 固定横版、白底。采用横向角色泳道，背景极浅，角色标签简洁；标题可按文档编号设置，无副标题或宣传语。
- 主流程：深蓝任务与较强的深蓝箭头，让读者首先辨认成功路径。判断使用橙色，异常使用红色；异常连线比主线细，但在文档实际尺寸下仍清晰。
- 节点：统一圆角任务卡；判断使用明确的菱形或一致的判断符号；开始/结束使用简洁事件符号。任务仅保留“动作名称 + 最多一行必要业务信息”。判断以短问题表达，条件放在分支箭头旁。长规则留在正文，以简短规则编号关联即可。
- 角色色彩：仅少量用于泳道标记，不让各角色任务分别变成大面积彩色卡片。图标使用同一套线性风格，可在无助于理解时省略；禁止混用 emoji、写实图与多套图标。
- 留白与对齐：同类节点尺寸、圆角、内边距和文字层级一致；跨泳道箭头采用规整折线，优先减少交叉。主线占据主要视觉空间，回流从外围经过，不穿越无关节点，也不遮挡标签。
- 图面不放图例、Slogan、业务对象栏、流程说明、关键规则卡或异常说明卡；它们由 PRD 正文承载。图中的分支条件、职责和必要语义仍须保留。若读者离开正文无法辨认复杂符号，应简化表达或改变交付形式，不以删掉语义来满足无图例要求。

可用起始参数（属于建议值，可随实际预览调整）：深蓝 #173B65、橙色 #C76A12、红色 #B83C45、泳道 #F5F7FA、正文 #243247。标题约 36 px、动作 24–28 px、辅助与条件文字 20–22 px；主线 3 px、次要或异常线 2 px。颜色只表达辅助层级，文字和形状同时表达语义。

## 从单张到成套

先选择一张包含典型交接、判断和回流、复杂度适中的流程做母版。没有用户指定时按代表性选择，不绑定固定文档章节或业务名称。

先完成逻辑核对与一张可审阅的完整图，再确定节点、字体、泳道、线型和颜色。用户要求先定母版时，交付这一张并等待反馈后再批量；已明确授权按既定样式批量时，沿用母版直接逐张处理。单张请求不增加额外审批环节。

每张流程单独检查，保持统一视觉参数，但根据真实角色数、节点数和回流结构调整布局。不要把母版中的角色或业务节点复制成后续图的默认事实。

画布拥挤时先简化重复措辞、重排节点或用明确命名的子流程拆图。不能只缩小全部内容、隐藏分支或靠裁切适配。文档可用宽度不足时优先采用横向页面或分页子流程；确需不同画布比例时，作为版式配置调整并保持全套一致。

## 不适用与方向选择

- 要求 BPMN XML、流程引擎执行、标准合规或完整事件语义：使用正式 BPMN 模型，此方法只可作辅助阅读图。
- 重点是前台触点、后台服务和支撑系统的分层体验：考虑 Service Blueprint。
- 重点是阶段价值、整体旅程而非审批与回流：考虑 Value Stream / Process Journey。
- 大规模事件或复杂循环无法清晰装入一张图：先分层、拆成总览与子流程，不强塞固定画布。
- 业务规则冲突或重要去向未知：停止定稿，提出具体缺口；不要用视觉推测业务事实。

## 完成依据

逻辑上：每个动作有责任归属；分支条件可辨；并行与互斥不同义；全部必要节点可从起点到达；每条路径按业务要求到达结束或明确回流；没有遗漏的交接或悬空箭头。

视觉上：主路径一眼可辨；异常清楚但不抢占主流程；节点仅含允许的信息；无外围说明模块；没有文字溢出、线穿节点、标签遮线或模糊交叉；全套视觉一致。

交付前实际打开导出的静态图，并在目标文档的真实嵌入尺寸下检查文字、线条和裁切。保存可编辑源稿。分别报告语义核对、导出检查和视觉检查结果；只检查源文件不能声称最终图面已验证。
