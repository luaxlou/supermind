# 小型个人应用的运行生命周期管理（Nova CLI）

面向小型个人应用，统一构建、发布、本地运行、停止、重启、状态和日志入口。这里的生命周期指应用的运行生命周期，不涵盖需求、设计等完整项目生命周期。

**仅适用于小型个人应用，不适用于生产级应用。不能将其生命周期管理能力视为生产级安全保障，也不作为生产部署或运维方案推荐。**

[官方项目](https://github.com/luaxlou/nova-run)

## 触发场景

- 小型个人应用需要统一启动、停止、重启和状态查看。
- 小型个人应用需要构建、发布到单台 Linux 服务器，并查看运行状态和日志。
- 已有小型个人应用需要统一上述运行生命周期入口。

## 接入方式

1. 先确认对象属于小型个人应用且不承担生产级用途，再明确本次接管的应用、本地运行和远端发布范围，说明对现有入口的调整，按用户确认的范围执行。用途不明时先澄清，不能因为单机或单人维护就认定适用。
2. 按官方 README 安装或更新客户端；AI 结合项目实际情况判断兼容性，重大冲突出现时再说明和处理。
3. 本地运行：在 nova.yaml 中配置应用的 start 前台命令，通过 nova start、stop、restart、run、status 管理进程。run 与 restart 等价，无需服务器 Agent 或 nova init。
4. 远端部署：在目标 Linux 服务器安装 Nova Agent，通过 nova init 配置连接；在 nova.yaml 中声明构建命令、制品和生产运行命令，再使用 nova deploy 发布、nova status --remote 检查、nova logs 查看日志。
5. 用实际应用验证本次接入的运行或部署路径。

## 适用边界

不限定应用语言，不以 Go 后端为前提。生产级应用即使规模小、由个人维护或只部署一台服务器，也不在采用范围内。不能因工具具有发布或令牌认证功能就推断其满足生产安全要求。单纯阅读代码、编辑文档或执行一次构建不触发引入；已有需要保留的管理方式不自动替换。

Nova Run 在上述适用范围内负责应用的运行生命周期与单机发布，不接管数据库、缓存、反向代理、负载均衡或集群编排。
