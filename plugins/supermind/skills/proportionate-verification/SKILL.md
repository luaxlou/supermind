# 按风险与证据决定验证

目的：用足够的证据支持交付，减少没有新增信息的测试与审查。节省时间不能替代正确性；测试数量和流程完成度也不能替代用户价值。

## 进入情境

在准备选择测试范围、扩大回归、接手他人的结果，或再次运行已通过的检查时使用。普通讨论不触发测试；不要为每条命令重新执行本技能或扫描整个项目。

利用已有的用户验收要求、实际 diff、依赖与构建变化、测试配置、失败日志、最近验证结果。只补充影响当前判断的材料，不新建强制表单、流程或数据库。

## 选择下一步

先确定尚未证实的行为或具体风险，再选择能够回答它的最低成本检查。必要时用一句话说明“改动影响什么、已有证据是什么、这次检查补什么”。常规微小改动不要求额外汇报。

| 情境 | 默认选择 | 扩大范围的依据 |
| --- | --- | --- |
| 普通说明或文案变更 | 阅读改动、链接或结构检查 | 文档含可执行示例、生成逻辑或会改变代理行为的指令时，验证受影响行为 |
| 局部逻辑修复 | 复现缺陷并运行相关行为测试 | 公共调用方、共享状态或依赖受影响 |
| 公共接口、存储、权限、同步、迁移 | 相关集成测试及关键失败路径 | 无法可靠限定影响面，或交付要求需要完整回归 |
| 审查交接 | 阅读 diff、实现者证据和未解决风险 | 证据不足、互相矛盾或发现新的具体缺陷 |
| 发布 | 对交付产物完成要求的验证，复用适用的既有结果 | 构建、依赖、配置、目标环境变化，或存在尚未覆盖的发布风险 |

不要机械设定测试时间比例、全量运行次数或用例数上限。成本高时先检查是否重复或范围过大；必要且耗时的检查仍应完成。

## 复用证据与重跑条件

一份可复用的结果至少能追溯：被验证的代码或产物（包含相关未提交改动）、命令与选择范围、相关依赖/配置/环境、结果和局限。沿用现有日志或任务记录即可。

提交号相同不保证输入相同；提交号变化也不自动使无关模块的证据失效。检查影响范围后决定，不建设新的通用缓存系统。

- 同一输入、同一环境、同一覆盖范围已通过，且没有新的具体疑点时，复用结果。换代理、进入审查、提交或换阶段都不是独立重跑理由。
- 相关实现、测试、共享 fixture、依赖、构建或环境变化时，重验受影响部分。无法限定影响时扩大回归。
- 全量命令已包含 E2E 时，不再以相同配置单独跑一次；真实安装产物、不同环境或不同数据的验收可能提供独立证据，应明确区别。
- 运行聚合验证脚本前，先确认它包含什么。不要在调用脚本前后无条件重复内部检查。
- 未知结果、被中断的运行、只启动未完成的检查，不能报为通过。保留日志并获取运行结果，不为改变输出样式重新执行测试。
- 排查 flaky test 或竞态时，可针对已提出的假设重复运行并设定诊断终点；不能重跑到绿再隐藏失败。

## 失败与审查如何收敛

先区分产品缺陷、测试假设过时、环境故障、需求/契约冲突。连续两轮仍在解决同一问题，是重新诊断和裁定契约的信号，不是停止修复真实缺陷的次数限制。

修复失败用例后，检查改动面：仅调整隔离的用例可先复测该用例；修改共享 fixture 或生产逻辑时覆盖受影响集合。不能直接推论其他所有用例仍然通过。

审查优先复用已有执行证据，集中检查行为、契约和风险。将独立发现尽量合并处理；复审针对修复及其影响。新发现的数据丢失、安全或重大正确性问题必须处理，不能以“只允许一轮”排除。

用户或项目明确要求的检查仍应完成。本技能不授权跳过强制门禁；若规则本身重复，指出具体重复，提出可审查的调整，不静默豁免。

## 完成与收益反馈

验收行为有证据、适用的必要检查通过、没有未解决的阻断问题，即继续交付。剩余不确定性应具体说明，不把“再保险一次”当作任务。

仅在存在实际数据时记录测试耗时、重跑理由、新发现的问题及后续回归。估计收益标为假设，不以少跑多少项或假定节省时间宣称成功；无需每次额外生成复盘文档。

## 来源与成熟度

源于 Supermind 开发任务 `01a06b67-c237-76f0-9948-c71dc956f2d0` 的 2026-09-07 复盘：基线 845 项测试耗时 485.85 秒；计划与聚合脚本存在重复调用；后期改用受影响测试、证据复用及不重叠的测试分组。

这是已抽取成技能的工程方法，尚未积累跨项目使用收益证据；不得据此宣称所有重跑均无效或已测得固定提效比例。
