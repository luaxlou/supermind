# 工程场景

工作范围为实现、验证、交付、运行维护和按已确认安排迁移退出。需求分析与设计属于上游输入；本场景目录不覆盖这些活动，也不在工程期间补作。

| 场景与进入条件 | 当前动作 | 工程能力检索时点 |
| --- | --- | --- |
| 规格变更、实施续接与归档 | 按 [OpenSpec](openspec.md) 使用官方 CLI、产物和唯一任务记录 | 用户选定的直接工具，不要求先查询或登记能力库 |
| 承接已明确需求与设计 | 读取有效依据，拆分必要实施步骤；缺少上游决定时交回具体问题 | 不因读取需求与设计而检索方法 |
| 按既定后端技术与职责接入基础代码 | 核对现有架构、接口及工程约定，比较兼容的实现基础 | 自行编写基础代码前；既定方案适用 Go 时可优先评估 Nova Go，不重新作架构选型 |
| 实现登录、文件处理、数据处理或外部集成 | 按已定行为和契约开发、适配并记录结果 | 自行实现通用能力前检索对应工程能力 |
| 按设计实现页面与交互 | 对照已有设计编码及核验，设计缺口交回上游 | 需要新的实现组件或工具时查询，不检索 UI 或交互设计方法 |
| 局部修改、缺陷修复或重构 | 调查期望与实际行为，完成直接相关改动 | 新增通用能力时查询，现有能力内的小改直接处理 |
| 建立本地运行方式 | 按实际启动命令建立运行入口 | 新写进程管理脚本前查询本地应用管理能力 |
| 验证与审查 | 对照既定验收要求，使用已有证据并补齐必要检查 | 引入新验证、诊断或审查能力前查询 |
| 建立单机部署方式 | 按目标环境、制品和已定运行约束落实部署 | 新写部署脚本或操作步骤前查询部署、进程和日志能力 |
| 按既有方式发布 | 核对内容及授权，执行发布并记录真实结果 | 沿用已采用能力，新的工程能力需求出现时查询 |
| 排障与性能优化 | 调查原因，在既有契约和架构内修复并测量结果 | 需要新的诊断、恢复或优化能力时查询；架构改动交回上游 |
| 实践复盘与沉淀 | 提取真实工程方法、代码或工具及适用边界 | 新增候选前查询已有相关成果，按确认范围登记 |
| 已决定的迁移、停用或退出 | 核对依赖与授权，执行既定安排 | 需要新的迁移、归档或清理能力时查询；未定的数据处置交回用户 |

## 从场景到调用

1. 按真实任务识别进入条件，读取必要的上游依据和工程事实。常规技术细节在已有约定内处理。
2. 沿用同一目标、范围与约束下仍有效的检索结果；新能力需求或重大兼容冲突出现时重新查询。
3. 使用现有 `RequirementProfile`，把工程用途写入 `intent`、已明确的必要行为写入 `contract`。这只是检索请求，不是需求分析。`id`、`project_id` 使用真实任务与项目标识；其他过滤字段按实际约束填写，不猜测技术栈。
4. 按入口技能完成初始化与健康检查。只查询候选或不允许来源发现时用 `search --input <requirement.json> --format json`。工程实施确需发现来源且授权允许时用 `begin-design --project-root <project> --input <requirement.json> --format json`。后者是兼容命令名，不启动设计流程，不为检索创建虚假项目。
5. 检查完整结果与故障状态，比较契约、来源、收益和接入成本；按已有规则取得具体复用授权后执行。需求分析或设计方法不因分类、名称或排序而成为可采用候选。

多个独立工程用途分别查询，不把后端基础、本地运行和远端部署合成一个契约。Nova Go 与 Nova CLI 分别按适用性选择。

### 建立本地运行方式

**进入条件：** 需要建立或改变本地一个或多个应用的运行入口。先识别应用、前台启动命令和需要保留的方式，在新建进程管理脚本之前查询。

**查询目标：** 满足当前应用启动、停止、重启等需求的本地管理能力，仅小型个人应用可考虑 Nova CLI。查询不预设 Go 后端，也不要求远端部署或服务器 Agent。

```json
{
  "id": "local-application-runtime",
  "project_id": "当前项目名称",
  "intent": "场景：建立本地应用运行方式。统一项目已有应用的进程操作，使用各应用真实启动命令。",
  "contract": "支持本地应用启动、停止和重启；本地操作不依赖远端服务器。"
}
```

**形成结果：** 明确接管哪些应用和替换哪些入口。Nova CLI 定位为小型个人应用的运行生命周期工具，不适用于生产级应用；单机或单人维护不等于适用。日常按既有配置启动、停止应用时不重复触发引入检索。

### 建立单机部署方式

**进入条件：** 需要建立或改变向单台服务器发布应用的方式。在新写部署方案或脚本之前，读取目标环境、制品和运行要求并查询。

**查询目标：** 项目需要的单机部署、远端应用管理和日志能力，仅小型个人应用可考虑 Nova CLI。它与本地运行、后端选型分别触发，不将三者强制绑定。

```json
{
  "id": "single-server-deployment",
  "project_id": "当前项目名称",
  "intent": "场景：建立单机部署方式。向目标服务器发布当前应用，统一部署后的运行与日志操作。",
  "contract": "支持应用制品部署到单台服务器，并提供远端进程管理和日志查看。"
}
```

**形成结果：** 说明目标、前提和接入影响，按已有或新确认的授权执行。Nova CLI 仅适用于小型个人应用的运行生命周期，不适用于生产级应用，不将其视为生产安全保障；用途符合后才评估 Linux Agent 等必要条件。不能在检索前擅自把项目限定为某个工具的支持范围。

## 其他明确触发与边界

用户明确要求查询或复用工程成果时直接围绕用途检索。用户要求沉淀工程经验时，登记前查找已有成果，判断更新或新增。库管理和插件安装更新按指定范围处理，不扫描项目来启动开发流程。

新的独立工程能力需求出现时重新检索，已有有效结果继续沿用。普通业务修改、既有方式的启动与发布不重复引入能力。

没有匹配结果可以在既定设计内考虑其他实现；检索故障不能据此新建替代能力。用户禁止库写入时按入口规则查询，不暗中修改或降级。无关的授权工作不因另一场景阻塞而整体停止。
