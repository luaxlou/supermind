# 基线方法的场景语境

生命周期用于理解当前背景，具体场景决定需要哪项能力和何时调用。需求与设计活动可在任何生命周期位置发生；不以进入设计阶段为由同时加载所有基线方法。

## 识别场景与缺失语境

| 场景进入条件 | 需要的方法与项目依据 |
| --- | --- |
| 建立或修订需求，目标、范围、规则或验收口径不清与冲突 | 需求基线方法；本次范围的有效决定、现行需求与未决项 |
| 表达、调整或对照界面结构、信息和交互 | UI 基线方法；已有界面设计与相关已确认需求 |
| 跨成果一致性、基线对齐推进、变更归档或任务交接需要管理 | 基线管理方法；现行依据、对应关系、对齐状态和后续安排 |

先读现有项目事实并判断本次场景。只取得需要且缺失的方法正文，现有有效语境直接沿用。UI 需要有效需求作为依据，不等于每次 UI 工作必须同时加载需求方法；需求缺口实际成立时才组合相应场景。无 UI 的工作不加载 UI 方法。

首次取得上述已知方法时，按技能入口执行不带项目发现的初始化和健康检查，再以对应标识读取完整正文：

- 需求：`inspect --view detail --capability-id engineering.requirements-baseline --format markdown`
- UI：`inspect --view detail --capability-id engineering.wireframe-design-baseline --format markdown`
- 一致性：`inspect --view detail --capability-id engineering.baseline-management --format markdown`

读取用于了解已知方法，不代表已获具体采用授权、已通过复用资格或已取得实践收益。实际采用仍遵守入口的资格与确认规则；需要比较、替换或选择其他能力时按场景形成完整检索需求。失败或缺失按能力库故障规则处理，不能假称已加载。

## 持续使用与恢复

取得方法后，按有效授权使用本次范围、现行决定及必要依据。换页面、改需求、阶段切换或任务续接不自动重查方法；更新受影响的项目内容与对齐状态即可。上下文丢失时补读缺失部分；用户要求更换方法或出现无法覆盖的新问题时重新选择相关能力。

交接交付当前结果、未决项、差异状态、下一步和授权边界；不要求同一任务走完设计、实施和验证。领域方法的完整正文留在能力库，此处只维护调用场景，不复制基线管理能力。

这些钩子由 AI 根据技能入口和场景指引识别执行，CLI 只提供检索与正文读取，不是自动事件监听器或新增阶段状态机。
