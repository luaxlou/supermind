# 上游成果承接

Supermind 的输入是当前范围已明确的需求、设计与验收依据。它们可以来自 ChatGPT、项目文档、用户消息或已有契约；不限定工具、模板或文件数量，也不要求提供 ChatGPT 对话访问权。

先读取已有材料，确认本次要实现什么、依据哪项有效决定、受哪些接口与工程约束限制、如何判断行为符合预期。只补读受影响范围，不进行需求分析、业务建模、架构设计或 UI 设计，不检索这些方法。

材料充分时直接实施。正常代码组织、配置和调试细节沿用项目约定，由 Codex 自行完成。没有正式文档的明确缺陷修复同样可执行。

缺少会改变实现结果的上游决定时，整理：已知依据、具体缺口或冲突、受影响的实现与验收项。交给用户在 ChatGPT 或其他上游协作中补充；不提出一套替代产品或设计方案，不自行推定业务规则。继续不依赖缺口的授权工作。

收到上游修订后，确认它替代哪些原有决定，更新受影响的工程计划、实现和验证记录。实际实现不一致时修正实现或报告障碍，不能以代码现状覆盖需求和设计。

工程交付说明实际改动、验证结果、未完成项与需要上游决定的问题。没有真实跨平台同步机制时，由用户传递材料；不声称已自动发送给 ChatGPT。
