# 设计阶段的持续语境

## 进入设计阶段时加载一次

当任务实际开始设计或进入一轮新的设计工作时，需求基线和 UI 基线共同构成阶段语境。基线建立、修订、对应和验收对照是设计阶段内的动作，不另设“基线管理”阶段，也不以每次动作作为重新查询的钩子。

先检查当前任务是否已经加载这两份方法及目标项目的现行基线。有效语境仍在时直接沿用。需要首次加载时，按技能入口执行不带项目发现的初始化和健康检查，然后分别读取：

- `inspect --view detail --capability-id engineering.requirements-baseline --format markdown`
- `inspect --view detail --capability-id engineering.wireframe-design-baseline --format markdown`

读取完整正文，不只读名称或检索摘要。两项是既定的设计阶段方法，不是每个动作重新选型的候选；无需为加载它们重复执行搜索。失败或缺失时按能力库规则报告实际缺口，不能假称已经加载。内容审查与库内成熟度分别保留，不将阶段加载解释为已取得实测收益或运行验证。

再读取采用方本次范围的需求、有效决定、现行 UI 线框及设计状态。尚无基线时，把缺口列入当前设计动作；没有 UI 的工作仍依赖需求基线，UI 基线标为不适用，不制造页面。仅出现“设计”字样、讨论插件分类或管理能力库，不算目标项目进入设计阶段。

## 整个阶段持续使用

阶段语境包含：已加载的方法、本次范围、现行需求版本和确认范围、UI 基线及其需求对应、待决事项和授权边界。沿用当前上下文和项目现有设计记录，不另建常驻服务、轮询任务或阶段数据库。

需求基线定义目标、范围、规则和验收；UI 基线依赖它，以确认后的线框图固定页面结构、信息和交互，供后续深化对照。分析、建模、接口设计、线框讨论、视觉深化、修订和设计验收都据此进行。需要确认的业务取舍仍需确认，已明确的决定和阶段内授权不因换页面、换动作或继续讨论失效。

- 切换页面或继续深化：使用已加载方法与当前基线，不重新查询能力库。
- 用户调整需求：更新项目中的需求决定及受影响 UI、模型、接口和验收项；这是语境更新，不是方法重新检索。
- 上下文压缩、任务续接：从现有记录恢复范围、基线和决定；只有方法正文实际丢失时补读，不把续接当成新一轮选型。
- 用户明确要求更换或更新方法，或出现当前方法无法覆盖的新问题：只重新取得受影响的方法。库有无新版本不实时轮询。
- 阶段结束：交付现行基线、设计结果与尚存差异，供实现和验证阶段引用。新一轮设计先恢复现有语境，再补充缺失部分。

这不取消后端框架、认证实现等独立技术能力在具体选型时的检索要求；那些是新的能力选择，不是反复加载设计阶段语境。

## 执行位置

钩子由 Supermind 的技能入口、核心决策和场景指引共同执行：识别进入阶段 → 加载缺失语境 → 阶段内持续应用 → 交付阶段结果。现有 CLI 负责取得能力正文，不提供自动阶段事件或常驻监听器；不能把文档指导说成已经存在的运行时钩子服务。
