# Supermind

Supermind 是 **Codex 平台下的工程执行能力**。承接用户在 ChatGPT 或其他上游协作中明确的需求与设计，通过工程实践、能力复用和持续记忆，将方案落实为可交付、可运行的软件。

## 工作分工

| 环节 | 承担方与成果 |
| --- | --- |
| 需求分析 | 用户与 ChatGPT 等上游协作，明确目标、范围、业务规则及验收条件 |
| 设计 | 上游完成业务模型、架构与系统方案、接口契约、UI 与交互设计 |
| 工程执行 | Codex + Supermind 承接成果，完成实施计划、编码、集成、调试、验证、交付及运维 |
| 执行中发现上游缺口 | Supermind 整理事实、问题与影响，交回上游补充决定，再继续受影响的实施 |

当前范围的依据足够即可开始，不要求全产品一次性完成正式文档。常规代码组织、实施步骤和调试方式由 Codex 按项目约定处理；需求分析与设计不属于 Supermind，在开发或运维期间出现也交回上游。

## 核心能力

- **承接工程工作**：读取有效需求、设计、已有代码和剩余问题，持续推进已授权范围。
- **实施与调试**：拆解既定方案，编码、集成、定位故障并修复，在现有契约内重构和优化。
- **验证与交付**：按风险和既有证据选择必要检查，处理版本、集成、发布与运行维护，准确区分已实现、已验证和已发布。
- **工程能力复用**：按场景检索代码、工具与工程方法，评估适用性及收益，按具体授权接入。
- **实践积累与记忆**：从真实工程工作和反馈中沉淀经验，沿用已有能力库、Git 提交与多端同步。

```mermaid
flowchart LR
    U[用户与 ChatGPT：需求分析和设计] --> I[明确的需求、设计和验收依据]
    I --> E[Codex + Supermind：工程执行]
    E --> R[实现、验证、交付与运行结果]
    E --> Q[上游缺口与工程事实]
    Q --> U
```

图中表示工作交接，不代表已实现 ChatGPT 与 Codex 的自动同步。用户可以提供项目文档、已有契约或明确指令，不限定上游工具。

## 安装或更新

把下面这段提示词复制给能够操作本机 Codex 的 AI：

```text
请帮我在本机 Codex 中安装或更新 Supermind。

项目地址：https://github.com/luaxlou/supermind
插件标识：supermind@supermind

先检查现有安装和插件源：未安装则安装，已安装则更新到远端 main 的最新发布状态。
请阅读项目的最新安装说明，使用 Codex 官方插件命令，从上述远端仓库安装，不使用本地开发目录或直接修改技能文件。
保留现有配置和能力库数据，不更新其他插件；缺少依赖、权限或认证时明确说明，不把失败当作成功。
完成后核对插件已启用、安装来源及版本，并告诉我验证结果，以及是否需要新建 Codex 任务才能生效。
```

同一段提示词既适用于首次安装，也适用于后续更新。

## 如何使用

在 Codex 任务中输入 `$supermind`，描述明确的工程目标，例如：

> 用 Supermind 按已确认的需求和设计实现手机号登录，验收依据见项目文档。

> 用 Supermind 排查登录回调失败，按现有认证契约修复。

> 用 Supermind 按已有部署方式发布这个版本。

> 用 Supermind 查看能力库，评估适合当前工程任务的登录实现。

需求分析、产品构想或设计请求交由上游处理。工程解释、局部修改和已明确的缺陷修复不要求先配置能力库。首次确需使用能力库时，指定或创建 GitHub 私有仓库并完成认证。
